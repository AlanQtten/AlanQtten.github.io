# 附录E：合集

在第一章，你已经看到了`cargo new`会在你的*Cargo.toml*中，其中就有关于合集的信息。本章会介绍这个配置的含义！

Rust语法和编译器以六周为一个发布周期，也就是说用户可以获取源源不断的新功能。其他的语言可能的发布会更慢，内容也会更多；Rust则选择更细小、频繁的更新。在一段时间后，这些细小的更新会累积起来。但如果只是在一些版本之间，可能很难回头说，“哇，Rust的1.10和1.31版本真是改动巨大啊！”

每三年左右，Rust团队会退出一个新的Rust*合集*。每个合集会对已落地的功能整合到一个包中，并提供完整的文档更新和工具链。新的合集会跟随六周的周期发布。

合集为不同的人群提供了不同的能力：

- 对于活跃的Rust用户，一个新的合集将各种增量更新引入了一个易于理解的包里
- 对于非用户来说，一个新的合集意味着一个新的里程碑，也使得Rust更值得被关注
- 对于Rust的开发者来说，一个新的合集可以为项目提供凝聚力

在本书撰写时，Rust有四个合集：Rust 2015、Rust 2018，Rust 2021和Rust 2024。本书使用Rust 2024合集的内容来撰写。

*Cargo.toml*中的`edition`关键字表明了编译器应该使用什么合集版本来看待你的代码。如果这个配置不存在，那么Rust会使用`2015`作为默认值，这是出于兼容性的考虑。

每个项目都可以选择2015合集以外的版本。合集可能会包含一些不兼容的改动，比如引入了一个新的关键字，和之前代码的标识符冲突。然而，除非你接收了这些改动，否则你的代码可以持续编译，即便你升级了你的Rust编译器版本。

所有的Rust编译器都支持任何在此之前发布的Rust合集，它们也可以链接使用任何合集版本的crate。合集的变化只会影响编译器对代码的解析。因此，如果你在使用Rust 2015，而你的依赖之一使用了Rust 2018，那么你的项目仍然可以编译并使用那个依赖。反之，如果你的项目使用了Rust 2018，而你的依赖使用了2015，也是可行的。

有一点需要澄清的是：大部分的功能在大部分的合集里都是可用的。使用任何的Rust合集都会看到持续不断的稳定版本。然而，在某些情况下，主要是来自关键字的增加，一些新的功能可能只能在新的合集里可用。如果你想体验那部分新功能，那么你需要切换合集的版本。

要了解更多细节，可以查看有关合理的完整描述：[合集指导](https://doc.rust-lang.org/stable/edition-guide/)，其中穷举了合集之间的不同，以及如何通过`cargo fix`自动升级你的代码。
