# 附录C：派生Trait

在本书的很多地方，我们都讨论了`derive`属性，它可以用在结构体和枚举的定义上。`derive`属性可以为使用了`derive`语法进行标注的类型自动生成一些通过trait默认实现来实现这个trait的代码。

在本节附录中，我们展示了标准库里所有的可派生trait。每一小节包括：

- 哪些运算符和方法会启用哪些trait的派生
- `derive`提供的trait实现做了什么
- trait实现的类型签名是什么
- 一个trait允许实现与否的条件是什么
- 一个要求trait的操作示例

如果你希望`derive`属性可以提供不同的行为，查看标准库文档来了解各个trait的细节，以及如何手动实现它们。

本节涉及的trait都是标准库中可以使用`derive`来为你的类型实现的trait。其他标准库里的trait没有默认行为的通用实践，所以需要你手动地根据你的情况来实现它们。

一个无法被派生的trait示例就是`Display`，它处理了面向终端用户的格式化。你需要自己考虑一个合适的方式来将一个类型展示给终端用户。类型的哪部分是用户被允许看到的？哪些部分是和他们相关的？使用什么格式最贴切？Rust编译器无法判断这一切，所以它无法为你提供默认行为。

本章提及的trait不是封闭的：库可以为他们自己的trait实现`derive`，扩大`derive`可使用的范围。实现`derive`涉及一些程序宏，这部分内容在第20章中有所介绍。

## `Debug`：提供调试输出

`Debug`trait可以提供格式化的字符串，你可以在`{}`占位符中使用`:?`来添加它。

`Debug`trait允许你打印类型实例用于调试，这样你和其他使用你的类型的开发者可以在程序执行的特定时间点解析实例。

比如，对于`assert_eq!`宏来说，`Debug`是必须的。这个宏会在相等判断失败时打印参数传入的实例信息，这样开发者可以查看实例之间的不同。

## `PartialEq`和`Eq`：提供相等性比较

`PartialEq`允许你使用`==`和`!=`来对比两个实例的相等性。

派生的`PartialEq`实现了`eq`方法。当`PartialEq`在一个结构体上派生时，两个实例会在*所有*属性相等时相等，如果任何的字段不相等，那么它们就不相等。在枚举上派生时，每个变体都需要和自身相等，不能和其他变体相等。

例如，在`assert_eq!`宏中，`PartialEq`是必须的，用于比较两个类型实例的相等性。

`Eq`trait没有任何方法。它是一个标记类型，表示对于被标记类型的每个值，它都和自身相等。`Eq`trait只能被实现了`PartialEq`的类型应用，但不是所有实现了`PartialEq`的类型都能实现`Eq`。比如浮点数字类型：浮点数的实现表明两个非数字实例（`NaN`）互不相等。

比如，`HashMap<K, V>`的键要求必须满足`Eq`，这样`HashMap<K, V>`才能判断两个键是否相等。

## `PartialOrd`和`Ord`：提供排序比较

`PartialOrd`trait允许你出于排序的目的对实例进行比较。一个实现了`PartialOrd`的类型可以使用`<`，`>`，`<=`和`>=`操作符。`PartialOrd`只能为实现了`PartialEq`的类型实现。

派生`PartialOrd`实现了`partial_cmp`方法，它返回一个`Option<Ordering>`，在值没有提供顺序时为`None`。即便大部分值都可以比较，但部分值无法比较的类型也可能返回`None`，比如非数浮点数（`NaN`）。调用`partial_cmp`对比任何的浮点数和`NaN`浮点数都会返回`None`。

在结构体上派生时，`PartialOrd`会逐一对比两个实例中各个字段的值，按照结构体定义时的顺序。在枚举上派生时，后定义的枚举变体权重由于先定义的枚举变体。

比如，对于`rand`crate的`gen_range`方法来说，`PartialEq`是必须的，因为生成一个范围内的随机数需要指定范围表达式。

`Ord`trait允许你对于标记类型的两个实例，一个有效的顺序是存在的。`Ord`trait实现了`cmp`方法，它会返回一个`Ordering`而不是一个`Option<Ordering>`，因为它的返回永远是有效的顺序。`Ord`trait只能为实现了`PartialOrd`和`Eq`的类型实现（`Eq`又依赖`PartialEq`）。在对结构体和枚举进行派生时，`cmp`的表现和`PartialOrd`的`partial_cmp`表现一致。

比如，对于在`BTreeSet<T>`中存储值时，`Ord`是必须的，因为这个数据结构是基于值的排序实现的。

## `Clone`和`Copy`：提供值的重复

`Clone`trait允许你显式地创建一个值的深拷贝，这个过程可能会涉及代码的运行和堆数据的赋值。你可以查看第四章的内容来了解关于`Clone`的更多细节。

派生`Clone`实现了`clone`方法，在对整个类型实现时，会调用类型各个部分的`clone`。也就是说，要派生`Clone`，所有类型里的字段或值都必须实现`Clone`。

比如，在调用切片类型的`to_vec`方法时，`Clone`是必须的。这个切片并没有其包含类型的所有权，但`to_vec`返回的vector需要包含对其中元素的所有权，所以`to_vec`方法需要调用每个元素的`clone`。因此切片中的类型必须实现`Clone`。

`Copy`trait允许你通过复制栈内信息来复制值；不会有额外的代码被执行，查看第四章来了解`Copy`的更多内容。

`Copy`trait不会定义任何的方法，这样的设计避免了开发者重载这些方法，从而违反没有代码被执行的前提。这样，所有人都可以预设复制值的速度非常快。

你可以对任何全部片段都实现了`Copy`的类型派生`Copy`。`Copy`只能为实现了`Clone`的类型实现，因为实现`Copy`的类型有一个琐碎的`Clone`实现，它的功能和`Copy`相同。

很少有情况要求必须实现`Copy`；实现了`Copy`的类型有可用的优化，也就是说你不需要调用`clone`，这样的代码更加简洁。

一切可以使用`Copy`的地方都可以使用`Clone`完成，但使用后者可能会导致代码变慢，某些地方也可能必须使用它。

## `Hash`：提供映射值和固定尺寸值

`Hash`trait允许你接收一个任意大小的类型值，并通过哈希函数将其映射到一个固定类型的值上。派生`Hash`会实现`hash`方法。`hash`方法的派生实现对类型的各个部分调用`hash`的结果进行了组合，所以要派生`Hash`，类型的各个部分都需要实现`Hash`。

对于使用`HashMap<K, V>`来高效存储键的场景，`Hash`是必须的。

## `Default`：提供默认值

`Default`trait允许你为一个类型创建默认值。派生`Default`会实现`default`函数。`default`函数的派生实现会调用类型各个部分的`default`函数，所以要派生`Default`，类型的各个部分都需要实现`Default`。

`Default::default`函数通常用于结构体更新语法的组合，我们在第五章讨论过这部分内容。你可以通过`..Default.default()`自定义结构体的一部分字段，然后使用其他字段的默认值。

`Default`trait对于一些方法来说是必须的，比如`Option<T>`实例的`unwrap_or_default`方法，如果`Option<T>`为`None`，那么`unwrap_or_default`会返回类型`T`的`Default::default`方法的返回值，并存储在`Option<T>`中。
